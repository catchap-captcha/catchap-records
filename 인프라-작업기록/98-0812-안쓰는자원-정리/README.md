### 원인 — 새 단계를 넣고 옛 단계 몸통을 안 지웠습니다

```yaml
        run: python3 .github/scripts/prune_tags.py
        if: steps.gate.outputs.ready == 'true'      # ← ★여기부터 8줄이 중복
        continue-on-error: true
        env:
          ...
        run: python3 .github/scripts/prune_tags.py
```

한 단계 안에 `if`·`continue-on-error`·`env`·`run` 이 **두 번씩** 들어갔습니다.

### ★왜 제 검사가 통과시켰나 — 검사기가 GitHub 보다 느슨했습니다

```
PyYAML safe_load  → 중복 키를 ★조용히 허용 (뒤엣것이 이김)  → 내 검사 통과
GitHub Actions    → 중복 키를 ★거부                      → 워크플로 전체 실패
```

저는 "YAML 을 파싱해서 확인했다"고 보고했습니다. **파싱은 했지만, 제 파서가
GitHub 의 파서보다 관대했습니다.** 통과가 통과를 뜻하지 않았습니다.

★**0811 과 같은 종류입니다** — 「같은 키를 두 번 쓰면 뒤엣것이 이긴다」.
그날은 GitHub Actions 출력 키였고, 오늘은 워크플로 YAML 키입니다.

★**빨간 표시가 났는데도 서비스는 멀쩡했습니다.** 이미 떠 있는 파드가 계속 받으니까

**VPC 로 갈라야 합니다** — 옛 VPC 는 `8dae313f…`, 새 VPC 는 `10aa8f6d…`.

🚫**옛 VPC 자체는 지우면 안 됩니다** — 같은 VPC 안에 남의 서브넷 4개가 살아 있습니다

★API 에서 콘솔 ID 는 「id」가 아니라 ★「name」입니다 (name = <콘솔ID>_<VPC ID>)

## 7-4. ✅미디어를 전용 버킷으로 분리했습니다 — 작동한 적 없던 격리

           뺌    Object Storage 매니저 · ★뷰어 · 프로젝트 멤버 · 프로젝트 리더
           남김  프로젝트 관리자(사람) · 버킷 소유자
복사       3,476개 15.68GB · 실패 0 · 빠진 것 0 · 크기 다른 것 0 (11분)
교체       MEDIA_BUCKET 한 줄 (PR #51) → ★수동 재기동 (체크섬 주석이 없다)
